        What runs offline, and what doesn't

        The face-matching model (a small on-device neural network) and this page's code are fetched once from a content delivery network. After that first load, your browser caches them and the check-in flow — camera capture, face comparison, fingerprint verification, and logging — runs entirely on this device with no server round-trip. If the model can't be fetched on first load (no internet yet), face scanning is disabled and staff can still use fingerprint/Face unlock or a PIN, which need no download at all.

        Fingerprint / Face unlock uses your device's own built-in biometric sensor (via WebAuthn) — a laptop's fingerprint reader, or a phone/tablet's Face ID or fingerprint. It never leaves this device.

        Storage: staff records and attendance logs are saved with IndexedDB, a browser database that lives on this device only, in this browser profile — no server, no internet needed to read or write it. That also means it's tied to this one device: if you deploy this to a single always-on kiosk tablet at the front office, everyone checks in on that one screen and its one local database. It won't sync across multiple devices or browsers, and clearing this browser's site data will erase it — export the CSV log regularly if you want a backup off the device.

        For a real school deployment on a dedicated check-in tablet, pair this with a proper fingerprint scanner peripheral or a purpose-built time clock; browser-based biometrics only work with sensors already built into the device.
